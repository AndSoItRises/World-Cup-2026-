## 2. THE HEADLINE FEATURE — two bankroll/performance trackers
Today there is ONE bankroll view: a 1,000-path forward Monte Carlo (`runBankroll()` in `build_dashboard.py`). It simulates *hypothetical* outcomes (coin-flips vs an assumed win prob), and it only includes bets where `market_source==='real'` AND `ev≥0.05` — so it covers a thin slice of games, not the tournament. Replace/augment with TWO distinct things:

### 2A. Model Performance Tracker — REALIZED, every value game, multi-strategy
The honest scorecard that answers "is the model actually good?"
- Universe: **every** match the model considered +value (edge over its threshold), across the whole tournament so far — NOT just matches with a real book line. Where no real line exists, use the de-vigged/fair price and **flag it** (`market_source`), don't silently drop it. This fixes the "not enough games" problem.
- For each such game, "place" the value bet and settle it against the **actual result** (reuse `settle_bets`' result logic / `wc2026_live_results.csv`) → realized P&L. This is a record of what happened, not a Monte Carlo.
- Run the SAME picks under **multiple betting strategies** (same data + model probs, different staking), and compare:
  - Flat stake (e.g. 1 unit / $15 each)
  - ¼-Kelly (capped 5%)
  - ½-Kelly (capped 5%)
  - Full-Kelly (capped 5%)
  - (optional) edge-proportional flat
- Report per strategy: ROI%, net units/$, hit-rate, max drawdown, Sharpe-ish, CLV alignment. One clean comparison chart + a verdict line ("model is +X% realized over N bets; ½-Kelly is the best risk-adjusted strategy so far").
- This is primarily **retrospective/realized**; an optional forward-MC projection can sit beneath it, clearly labeled as projection.

### 2B. MAIN Bankroll Simulator — $500, starting TODAY, selective best picks
The hero number a user cares about: "if I gave this model $500 today, what happens?"
- **Starts at $500 on the current date** (do not retro-credit earlier tournament games — this is "from today forward").
- **Selective:** the model only bets games it likes (its best calls) — it is allowed to PASS. Not every fixture.
- Tracks **realized** bankroll as remaining results land (knockouts etc.), with an optional forward-MC projection cone for fixtures not yet played.
- This is the headline/most-prominent bankroll view. Make the current value + curve impossible to miss.
- Persist its state so it accumulates over time (a ledger/JSON the dashboard reads), consistent with the append-only ledger pattern already used (`bet_ledger`, `prediction_ledger`).

**Data you already have for both** (in `data/processed/` unless noted): `value_bets.csv` (edge/EV/Kelly per outcome, `market_source`), `clv_report.csv` + `bet_ledger_settled.csv` (settled picks + pnl), `prediction_ledger.csv` (per-match model + Shin-fair market 1X2, logged pre-result), `prediction_scoreboard.csv`, `wc2026_live_results.csv` (raw, actual scores), `wc2026_fixtures.csv` (the match_id key; remaining fixtures = not in live results), `insurance_summary.json`, `model_health.json`. Settlement helper: `src/models/settle_bets.py` (`load_results()`, `result_side`).

Open design choices to confirm with Jake or default sensibly (and log the choice): exact strategy list for 2A; whether 2B's forward projection is on by default; odds source for not-yet-played games (fair vs live book); unit size ($15, from `config.json`).
